Why Modern Excel?

Power Query or VBA? A quick refresher for anyone still deciding

If you've been using Excel for a while, you've probably got a few macros somewhere doing the heavy lifting - pulling data together, formatting reports, maybe even emailing files out automatically. VBA has been doing that job well for over twenty years, and there's nothing wrong with that.

But Excel has changed a lot in the background, and one of the more useful additions is a tool called Power Query. If you haven't come across it yet, or you've heard the name but never quite got around to it, here's a plain English refresher.

What Power Query actually does

Power Query is a built in tool (found under the Data tab in modern versions of Excel) that connects to your data, cleans it up, and reshapes it - without you having to write any code. You build a series of steps - remove this column, split that one, filter out blanks - and Excel remembers every step. Next month, when the new data arrives, you click Refresh and the whole process runs again automatically.

That's the part that makes it a genuine alternative to a lot of what VBA has traditionally been used for: combining files, cleaning up exports from other systems, restructuring data before it goes into a report.

So is VBA on the way out?

Not really, and it's worth being upfront about that. VBA still does things Power Query can't:

  • Building custom dialog boxes or interactive tools
  • Automating actions across other applications (Outlook, Word, other workbooks)
  • Handling very specific, one-off logic that doesn't fit a repeatable data transformation

The shift isn't "replace VBA with Power Query." It's more that Power Query has taken over the data preparation work VBA was often pressed into doing, which frees VBA up for the jobs it's actually well suited to - or removes the need for it altogether in simpler workbooks.

Why this matters if you're relying on an old spreadsheet

A lot of nonprofits and small teams have at least one spreadsheet that "just works" but that nobody wants to touch, because the macro behind it was written by someone who left years ago. That's a risk, not just an inconvenience. If it breaks, or the process needs to change, there's often no one left who understands it.

Rebuilding that kind of process using Power Query (with VBA kept only where it's genuinely needed) tends to leave you with something more transparent. Each step is visible and can be edited without opening a code editor, which means the next person who inherits the file - even if that's future you - has a fighting chance of understanding it.

The short version

Power Query is now the better starting point for most data preparation and reporting tasks in Excel. VBA still has a place, particularly for automation that goes beyond data transformation, but it's better used deliberately and sparingly rather than as the default tool for everything.

If you've got a spreadsheet you suspect falls into the "nobody wants to touch it" category, that's exactly the kind of thing worth a second look.
